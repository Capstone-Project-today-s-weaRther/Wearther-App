# WEARther — 날씨 기반 코디 추천 시연 웹앱

React + Vite 기반의 모바일 앱형 웹앱입니다. 1~11번으로 제공된 화면 디자인을 기준으로 시작·위치·사전조사·로딩·환영·홈·지역변경·날씨·오늘의 추천·리뷰 작성·마이페이지를 재구성했습니다. 데스크톱에서는 중앙에 모바일 앱 프레임으로, 스마트폰에서는 화면 전체로 표시됩니다.

## 1. 로컬 실행

Node.js 20 이상 권장. Windows에서는 Node.js 설치 후 시작 메뉴의 **Node.js command prompt**를 열어 명령을 실행해도 됩니다. PowerShell에서 `npm`이 인식되지 않으면 Node.js 설치 경로(일반적으로 `C:\Program Files\nodejs\`)가 PATH에 등록되어 있는지 확인하세요.

```bash
npm install
cp .env.example .env
# .env의 Supabase / 기상청 키를 입력
npm run dev
```

브라우저에서 `http://localhost:5174/`를 엽니다. Vite 개발 서버는 `localhost`의 5174 포트로 실행합니다.

키를 입력하지 않아도 로컬 CSV 미러 데이터로 시연할 수 있습니다. 이 경우 날씨는 샘플(7°C)로 표시되며 화면에 시연 데이터라고 안내합니다.

## 2. 환경변수 입력

프로젝트 루트의 `.env` 파일을 만들고 아래 값을 입력합니다.

```dotenv
# Supabase > Project Settings > API > Project URL
VITE_SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co

# Supabase > Project Settings > API > Project API keys > anon / publishable key
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY

# 공공데이터포털 > 기상청 단기예보 조회서비스 > 일반 인증키(Decoding)
# 반드시 VITE_ 접두사 없이 서버 환경변수로 둡니다.
KMA_SERVICE_KEY=YOUR_KMA_DECODING_SERVICE_KEY
```

- `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`: 브라우저에서 사용하는 공개 설정값입니다. Supabase RLS 정책을 반드시 적용하세요.
- `KMA_SERVICE_KEY`: 기상청 인증키입니다. `VITE_` 접두사를 붙이면 브라우저 번들에 노출되므로 절대 붙이지 마세요.
- 기상청 키는 공공데이터포털의 **일반 인증키(Decoding)** 사용을 권장합니다. Encoding 키를 사용하는 경우 이중 URL 인코딩 문제가 발생할 수 있습니다.
- `.env` 파일은 Git에 올리지 않도록 `.gitignore`에 등록되어 있습니다.

## 3. Supabase 준비 순서

Supabase SQL Editor에서 아래 순서로 실행합니다.

1. `supabase/supabase_recommendations_setup.sql` — 제공받은 기존 통합 설정 SQL 원본
2. `supabase/supabase_demo_policies_and_region_search.sql` — 지역 검색 보강 및 시연용 RLS 정책

앱에서 사용하는 주요 테이블/RPC:

- `region_map`: 행정구역 + 권역(zone) + 기상청 격자(nx, ny)
- `region_preset`: 주요 지역 별칭
- `fashion_images`: 권역별 착용 데이터 및 Pexels 이미지
- `weather_clothing_map`: 기온 구간별 기준 의류
- `region_adjust`: 권역별 기온 보정치
- `outfit_feedback`: 세션 리뷰 기록
- `search_regions`, `get_session_temp_offset`, `submit_outfit_feedback`: 지역 검색 및 피드백 RPC

`region_map` 검색이 RPC로 동작하지 않으면 제공된 CSV 미러를 자동 사용합니다. `fashion_images`를 조회하지 못하는 경우에도 업로드된 1,141행 데이터가 로컬 미러로 제공됩니다.

## 4. 기능 흐름

- 시작 화면의 Google 버튼은 OAuth 로그인을 수행하지 않는 시연용 가짜 동의창입니다. `취소` 또는 `계속`을 누르면 `로그인을 건너뜁니다.` 팝업이 나타나고 지역 설정으로 이동합니다.
- 지역 설정은 필수입니다. 현위치 권한 사용 또는 지역 직접 검색 중 하나를 선택해야 사전조사로 넘어갑니다.
- 지역 검색은 시·군·구 전체와 세부 읍·면·동 선택을 지원합니다. 선택한 지역을 확정해야 다음 단계로 넘어갑니다.
- 사전조사에서 성별, 체감온도 성향, 닉네임(2자 이상)을 입력합니다. 입력값은 시연 브라우저의 `localStorage`에 저장됩니다.
- 조사 완료 뒤 닉네임을 표시하는 로딩 화면을 거쳐, 체감 성향을 반영한 환영 바텀시트가 나타납니다.
- 지역 선택 시 해당 행의 `nx`, `ny`로 기상청 초단기실황/단기예보 API를 서버에서 호출합니다.
- 선택 지역의 `zone`에 해당하는 `fashion_images` 행만 조회합니다. `image_url`이 Pexels CDN인 데이터만 사용하고, 의류 배열에서 상의 항목만 분리해 Top 4를 만듭니다. 홈의 거리 스타일 카드 및 오늘의 추천 화면은 해당 권역 데이터만 사용합니다.
- 오늘의 코디/날씨/Top 4는 지역을 바꾸기 전까지 `localStorage`의 일일 스냅샷을 재사용합니다. 지역을 다시 선택하면 새로 계산합니다.
- 추웠어요/딱 좋았어요/더웠어요 리뷰는 Supabase `outfit_feedback` 및 기존 RPC에 저장합니다. 브라우저 시연 모드에서는 `localStorage`에도 저장되며, 오늘의 추천 화면과 마이페이지에서 확인할 수 있습니다. 리뷰 등록 완료 후 `아니요`를 누르면 오늘의 추천으로, `마이페이지로`를 누르면 MY 화면으로 이동합니다.
- 리뷰 기반 체감 기온 보정치는 최근 5개 리뷰 기준으로 다음 지역 갱신 시 적용됩니다. 이미 불러온 날씨·코디 스냅샷은 지역을 다시 선택하기 전까지 그대로 유지됩니다.

## 5. 2차 피드백 반영 사항

- 모든 화면에서 상단 운영체제 상태바(시간·Wi-Fi·배터리)를 숨겼습니다.
- 초기 지역을 선택하면 `지역 설정 중...` 회전 표시를 보여주고, `지역 설정 완료` 상태를 약 2초 보여준 뒤 성별 조사로 넘어갑니다.
- 시간대별 예보는 기상청 응답의 현재 관측값과 오늘 남은 예보를 표시하며, 가로 스와이프와 좌우 화살표로 이동합니다. 기상청에서 제공하지 않는 시간값을 임의 생성하지 않습니다.
- 주간 예보의 작은 날씨 아이콘은 독립된 34px 영역에 배치해 겹침을 방지했습니다. 최고/최저·습도·풍속·강수확률은 동일한 4열 그리드로 정렬합니다.
- 오늘의 코디 이름은 실제 선택된 상의·아우터 이름을 조합해 생성하고, 아이템은 작은 키워드 칩으로 표시합니다. DB의 `주말코디`, `주말룩`, `코디추천` 같은 게시글 태그는 제목에 사용하지 않습니다.
- MY 화면의 닉네임 아래 성별 메타정보는 제거했습니다.
- 리뷰 의견은 선택 입력이며, 입력하는 경우 1자부터 저장할 수 있습니다. 평가(추웠어요/딱 좋았어요/더웠어요)는 필수입니다.
- 프로필 사진 영역에서 컴퓨터 파일을 선택하거나, 브라우저 권한을 허용한 뒤 카메라 촬영을 할 수 있습니다. 이미지는 최대 560px로 축소해 브라우저 시연 프로필에 저장합니다.
- 거리 스타일 카드의 상의 사진은 `src/data-mirror/top-image-map.json`의 상의명별 매핑을 우선 사용합니다. 현재 CSV에서 확인된 상의 9종을 매핑했으며, 나머지 신규 의류명은 기존 DB 행의 사진을 대체 이미지로 사용합니다.

### 착용 이미지 파일 관련

이번 2차 디자인 ZIP에는 UI 스크린샷(3~11번)만 있고, 별도의 사진 원본 파일 묶음은 포함되어 있지 않았습니다. 또한 이 작업 환경은 외부 이미지 서버 DNS 연결이 제한되어 사진 파일을 로컬로 내려받을 수 없었습니다. 따라서 사진 자체를 `public/assets`에 복사하는 대신 Pexels CDN URL과 출처를 항목별 JSON 매니페스트에 포함했습니다. 실행 환경에서 인터넷 연결이 되어 있으면 카드 사진이 로드됩니다. 완전한 오프라인 실행이 필요하다면 해당 CDN 사진을 다운로드해 `public/assets/top-style/`에 넣고 매니페스트의 `image_url`을 로컬 경로로 바꾸면 됩니다.

## 6. 배포

Vercel 기준으로 준비되어 있습니다.

1. GitHub에 프로젝트 폴더를 push합니다.
2. Vercel에서 저장소를 import합니다.
3. Project Settings → Environment Variables에 `.env`와 같은 변수 3개를 등록합니다.
4. Build Command: `npm run build`, Output Directory: `dist`.

`api/weather.js`는 Vercel Serverless Function으로 배포되어 기상청 키를 서버에서만 사용합니다. 로컬에서는 Vite middleware가 같은 `/api/weather` 경로를 처리합니다.

## 7. 현재 데이터 기준 참고 사항

- 업로드된 `region_map_rows.csv`에는 `전북특별자치도 군산시 나운동` 행이 있으나 `나운1동`, `나운2동` 행은 포함되어 있지 않습니다. 앱은 실제 데이터에 없는 행정구역을 임의로 만들어 표시하지 않습니다. 추후 `region_map`에 해당 행을 추가하면 검색 결과에 자동 반영됩니다.
- 제공된 `fashion_images` 데이터는 권역별로 Pexels 이미지 URL을 포함하고 있습니다. 상의 Top 4는 `src/data-mirror/top-image-map.json`에서 의상명과 Pexels 착용 사진을 1:1로 매칭합니다. 항목별 Pexels 원본 페이지·촬영자·대체 이미지 URL을 함께 기록했습니다. Pexels CDN 이미지는 실행 중 인터넷으로 불러옵니다(사진 바이너리 파일을 오프라인으로 포함한 것은 아닙니다). Pexels 이미지의 게시·상업적 활용 전에는 원본 사진 페이지와 Pexels 라이선스를 다시 확인하세요.
- 사전조사 프로필(성별·체감 성향·닉네임)은 현재 시연용으로 브라우저 `localStorage`에 저장되며 Supabase Auth 계정은 생성하지 않습니다. 현재 시연 로그인은 Google 계정 인증 없이 브라우저별 랜덤 세션 ID를 사용합니다. 앱은 `x-wearther-session` 요청 헤더를 보내고, 리뷰 테이블은 같은 세션의 행만 읽고 쓰도록 RLS를 제한합니다. 이는 데모용 구분자일 뿐 실제 사용자 인증이나 강한 보안 경계가 아니므로, 실제 서비스 전에는 Supabase Auth 또는 서버 검증 세션과 사용자별 소유권 정책을 적용해야 합니다.

## 8. 공식 문서 및 이미지 라이선스

- 기상청 단기예보 조회서비스(공공데이터포털): https://www.data.go.kr/data/15084084/openapi.do
  - 이 앱은 `getUltraSrtNcst`와 `getVilageFcst`를 사용하며, 지역별 격자 좌표 `nx`, `ny`를 전달합니다. 단기예보는 7일 전체를 제공하지 않으므로, 날씨 화면의 실제 예보는 API 응답이 있는 날짜만 표시하고 나머지는 `예보 미제공`으로 둡니다. API 키가 없는 로컬 시연 모드에서는 구분을 위해 샘플 7일 데이터를 표시합니다.
  - 공공데이터포털에서 받은 서비스키를 `KMA_SERVICE_KEY`에 넣습니다.
- Pexels 라이선스: https://www.pexels.com/license/
  - Pexels는 사진·영상을 무료로 제공하며 상업적 웹사이트/앱 이용도 허용한다고 안내합니다. 저작자 표시는 필수는 아니지만 항목별 촬영자와 원본 Pexels 페이지 정보를 매니페스트에 보관했습니다.
  - 사진 속 인물·브랜드가 앱을 보증하거나 후원하는 것처럼 표현하지 말고, 사진을 원본 그대로 별도 재판매하거나 스톡 이미지 서비스처럼 재배포하지 마세요.

## 9. 새 UI 화면 기준 및 프로필 처리

- 번호별 원본 디자인은 `design-reference/screens/1.png`~`11.png`에 포함되어 있습니다. 2차 디자인 ZIP에는 3~11번만 있어 1~2번은 1차 디자인 파일을 유지했습니다.
- 홈/날씨/오늘의 추천/MY는 3탭 하단 내비게이션과 iPhone형 화면 비율을 기준으로 구성했습니다. 데스크톱에서는 중앙에 앱 프레임으로 표시되고 모바일에서는 화면 전체를 사용합니다.
- 성별과 닉네임, 체감 성향은 시연용 프로필로 브라우저에 저장됩니다. 체감 성향은 추천용 체감 기온 보정에 반영됩니다(추위 민감 -1.5°C, 더위 민감 +1.5°C).
- **성별 기반 의상 필터링은 현재 데이터로는 아직 불가능합니다.** 업로드된 `fashion_images_rows.csv`/현재 테이블 조회 컬럼에는 성별 또는 `target_gender`가 없습니다. 성별별 추천을 실제로 구분하려면 패션 이미지 각 행에 정확한 성별/유니섹스 메타데이터를 추가해야 합니다. 현재 앱은 선택값을 보관하지만 임의로 사진 성별을 추정해 필터링하지 않습니다.
- 기상청 단기예보는 7일치 전체가 아닌 제공 기간까지만 실제 값을 반환할 수 있습니다. 날씨 상세 화면은 API가 제공하는 날짜를 실제 값으로 보여주며 나머지는 `예보 미제공`으로 표시합니다. 키 미설정 시 시연 샘플 7일 예보가 표시됩니다.
- 권역별 상의 종류 수는 현재 데이터에 따라 다릅니다. 제공된 Pexels 행과 상의 분류 기준으로 부산·제주 권역은 고유 상의 항목이 3종이라 해당 지역에서는 3개까지만 표시될 수 있습니다. 다른 권역의 항목을 섞거나 아우터를 임의로 상의에 포함하지 않습니다.


## 10. 3차 피드백: 시연 초기화 및 브랜드 로고

- 모든 화면의 브라우저 모서리에 `처음부터 다시 시연` 버튼을 표시합니다. 버튼을 누르고 확인하면 `wearther_` 접두사가 붙은 localStorage/sessionStorage 데이터를 지운 뒤 페이지를 새로고침합니다. 첫 화면으로 돌아오며, 다음 실행에서 새 시연 세션 ID가 만들어집니다.
- 초기화 대상에는 현재 세션 ID, 지역 설정, 설문 응답, 닉네임, 프로필 사진, 오늘의 날씨/코디 스냅샷, 브라우저에 저장한 리뷰가 포함됩니다.
- Supabase에 이미 저장된 이전 리뷰 행은 삭제하지 않습니다. 다만 새 세션 ID가 발급되므로 새 시연에서는 이전 리뷰와 해당 세션의 피드백 온도 보정값이 조회되지 않습니다. DB 원본까지 삭제하려면 별도 관리자 SQL을 실행해야 하며, 반복 시연 편의 기능에서는 공유 DB의 다른 사용자 데이터를 지우지 않도록 설계했습니다.
- 시작 화면의 로고/워드마크는 사용자가 제공한 `2.png` 원본 이미지를 사용합니다. 환영 바텀시트의 닉네임은 괄호 없이 `{nickname}님!` 형식으로 표시합니다.
- 이번에 업로드된 `ui화면_디자인3.zip`에는 `2.png`, `5.png`만 포함되어 있습니다. 이 중 `2.png`는 시작 화면 브랜드 이미지로 적용했고, `5.png`는 환영 바텀시트 참고 이미지로 보관했습니다. 요청에 언급된 별도 `3.png` 파일은 ZIP에 포함되어 있지 않아 독립적인 추가 디자인 교체에는 사용하지 않았습니다.

### 브라우저에서 수동 초기화하는 방법

앱의 `처음부터 다시 시연` 버튼을 누르는 것이 가장 쉽습니다. 수동으로 하려면 브라우저 개발자 도구(F12) → Console에서 아래 코드를 실행한 뒤 새로고침합니다.

```js
Object.keys(localStorage).filter((key) => key.startsWith('wearther_')).forEach((key) => localStorage.removeItem(key));
location.reload();
```


## 4차 시작 화면 브랜드 비율 수정
- 로고와 한글/영문 워드마크는 1번 디자인의 원본 이미지에서 분리한 투명 PNG를 사용합니다.
- 요소 크기·위치는 2번 디자인 레퍼런스 비율(로고 상단 약 26%, 한글 워드마크 약 40%, 영문 서브타이틀 약 46%, 로그인 버튼 하단 약 22%)로 조정했습니다.
- 기존 앱 기능과 나머지 화면은 변경하지 않았습니다.

## 5차 피드백: 설문 진행표시, 파비콘, 히트텍 이미지
- 사전조사 3단계 화면의 우측 상단 `1/3`, `2/3`, `3/3` 진행표시만 제거했습니다. 본문 상단의 단계 표시는 유지하고, 좌측 뒤로가기 버튼도 유지합니다.
- 브라우저 탭 파비콘은 사용자가 제공한 5차 `5.svg` 원본을 `public/favicon.svg`로 등록했습니다. `index.html`에서 SVG 파비콘으로 참조합니다.
- 홈 화면 `지금 거리의 스타일`에서 `히트텍` 항목은 몸에 맞는 검정색 긴팔 상의 착용 사진으로 변경했습니다. Pexels 사진 ID 10518401, 촬영자 Anastasia Maksimova의 무료 사진을 사용하며, 원본 페이지와 설명은 `src/data-mirror/top-image-map.json` 및 `public/data/top-image-map.json`에 기록했습니다.
- 히트텍 이미지는 기존 프로젝트의 다른 이미지처럼 Pexels CDN에서 로드합니다. 따라서 표시할 때 인터넷 연결이 필요하며, 사진 원본 파일은 이 실행 환경의 외부 DNS 제한으로 ZIP에 로컬 포함하지 못했습니다.
- 5차로 전달된 1~7번 디자인 원본은 `design-reference/round-5/`에 보관합니다.


## 현위치 행정구역 매칭 보완 (최근 수정)

현위치 선택 시 브라우저에서 매번 새 고정밀 좌표를 요청합니다(`enableHighAccuracy: true`, `maximumAge: 0`). Nominatim 역지오코딩 결과의 상위 행정구역 필드는 다음과 같이 해석합니다.

- `city=서울특별시`처럼 Nominatim의 `city` 필드에 시도가 들어오는 응답도 시도 식별에 사용합니다.
- `borough=마포구`를 시군구로 사용합니다.
- `suburb=서강동`을 행정동 후보로 먼저 확인합니다.
- `neighbourhood=17통`은 통 단위의 작은 생활권 정보로 보고 법정동 이름으로 변환하지 않습니다. `통`을 `동`으로 자동 치환하면 실제 존재하지 않는 행정구역을 선택할 수 있기 때문입니다.

현재 제공된 `region_map`에는 서울특별시 마포구의 `서강동` 행이 없고, 마포구 전체를 대표하는 집계 행이 있습니다. 따라서 실제 응답인 `서울특별시 / 마포구 / 서강동 / 17통`에서는 **마포구 집계 행으로 권역(zone)을 확인하고, 날씨 API용 KMA nx/ny는 실제 GPS 위도·경도를 KMA 5km Lambert Conformal Conic 격자로 변환해 계산**합니다. 화면에는 역지오코딩으로 확인된 `서강동`을 표시합니다. 이렇게 하면 행정동이 `region_map`에 개별 행으로 없어도 주소 표시와 날씨 격자 계산을 분리해 처리할 수 있습니다. 상위 시도·시군구까지 확인되지 않으면 다른 지역을 임의로 선택하지 않고 직접 지역 선택을 요청합니다.

현위치 매칭 테스트 실행:

```bash
npm run test:location
```

테스트는 실제 Nominatim 필드 조합(`city`, `borough`, `suburb`, `neighbourhood`), `17통` 오매핑 방지, 존재하는 법정동의 정확한 선택, 상위 행정구역 불일치 거부, 시군구 집계행 대체 및 실제 GPS 좌표의 KMA 격자 변환을 확인합니다.

개발 서버는 Windows에서 이전에 발생한 소켓 바인딩 오류를 피하도록 `http://localhost:5174/`에서 실행하도록 설정했습니다.
